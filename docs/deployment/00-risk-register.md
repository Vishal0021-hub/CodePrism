# Phase 00: Deployment Risk Register

This document tracks all identified risks in preparing, configuring, and deploying CodePrism to AWS under the Single-EC2, single-origin architecture and $100–$200 credit budget.

| ID | Risk | Severity | Potential Impact | Planned Mitigation / Fix | Target Phase |
|---|---|---|---|---|---|
| **RSK-01** | **Next.js API Base URL Defaulting to Localhost** | **High** | In production, client API calls point to `http://localhost:8081` instead of relative paths, breaking authentication and data loading for external visitors. | Adjust `getApiBaseUrl()` in `client/lib/api.ts` to allow empty string `""` so relative URLs (`/api/...`) are used behind Nginx single-origin reverse proxy. | Phase 01 |
| **RSK-02** | **SSE Buffering in Nginx Reverse Proxy** | **High** | Nginx buffers Server-Sent Events (SSE) by default. Users will see a spinning indicator and receive all chat tokens at once at the end instead of real-time streaming. | Configure `proxy_buffering off;`, `proxy_read_timeout 300s;`, and `chunked_transfer_encoding on;` in Nginx site configuration. | Phase 02 / B03 |
| **RSK-03** | **EC2 Out-Of-Memory (OOM) Under Load** | **High** | Running PostgreSQL + pgvector, Spring Boot JVM (Java 21), Next.js Node runtime, and Nginx on a small EC2 instance (e.g., 2GB RAM `t4g.small` or `t3.small`) can cause the Linux OOM killer to terminate PostgreSQL or Java. | 1. Configure Linux Swap (2GB–4GB swapfile).<br>2. Set JVM heap caps (`-Xms256m -Xmx512m`).<br>3. Set Docker container memory limits in `docker-compose.yml`. | Phase 01 / Phase B04 |
| **RSK-04** | **Database Persistence & Data Loss on Container Recreation** | **Medium** | Recreating containers during deployments could destroy repository vector embeddings and user sessions if persistent volume mapping is misconfigured. | Use named Docker volume (`codeprism_pgdata`) mounted to `/var/lib/postgresql/data` with host backup scripts. | Phase 01 / Phase B03 |
| **RSK-05** | **CloudFront Header Stripping (Cookies & OAuth)** | **Medium** | CloudFront default cache behavior strips `Cookie` headers and query strings, preventing OAuth2 callback code processing and breaking session cookie `CODEPRISM_SESSION`. | Set CloudFront Cache Policy to pass through all headers, cookies (`CODEPRISM_SESSION`), and query strings for `/api/*` and `/oauth2/*`. | Phase B06 |
| **RSK-06** | **GitHub OAuth Callback URL Mismatch** | **Medium** | After deployment to CloudFront (`https://xxxx.cloudfront.net`), GitHub OAuth login fails with `redirect_uri_mismatch` if GitHub OAuth app settings aren't updated. | Document the exact OAuth Authorization callback URL (`https://<distribution-id>.cloudfront.net/login/oauth2/code/github`) for the owner to update in GitHub Developer Settings. | Phase B05 / B07 |
| **RSK-07** | **Hibernate `ddl-auto=update` in Production** | **Low** | Automatically updating table schemas on startup can lead to unintended schema locks or column drift over time. | Acceptable for MVP on single instance; prepare a baseline schema export or Flyway migration plan for subsequent releases. | Phase B08 |
| **RSK-08** | **AWS Credit Burn & Cost Overrun** | **Medium** | Forgotten resources (e.g. unattached EBS volumes, elastic IPs, or high-tier instances) could burn through the $100–$200 credit pool before 6 months. | Stick strictly to single `t4g.small` ($0.0168/hr $\approx$ $12/month) or `t3.small` ($0.0208/hr $\approx$ $15/month) + CloudFront free tier (1TB/mo free). Setup AWS Billing Alert at $15/month. | Phase 00 / Every Phase |
